# 실사용 검증 및 스윙 데이터 수집 계획

공개 데이터로 해결하지 못한 핵심 문제는 **손에 쥔 휴대폰의 IMU 신호와 실제 공 결과(볼 스피드, 발사각, 스핀, 방향)를 함께 기록한 데이터가 없다**는 점입니다. 이 문서는 그 데이터를 모으는 순서를 정리합니다.

## 1단계: 앱 기본 동작 확인 (개발자 1명, 1~2시간)

| 확인 항목 | 방법 | 통과 기준 |
|---|---|---|
| 설치·실행 | APK 설치 후 실행 | 가로 화면, 메뉴 표시, 강제 종료 없음 |
| 실제 샘플링 속도 | 센서 분석 화면의 "실측 Hz" | 150 Hz 이상 (200 Hz 요청) |
| 센서 범위 | 센서 정보 카드 | 가속도 ±78~157 m/s², 자이로 ±34.9 rad/s 이상 |
| 정지 판정 | 스윙 게임 → 스윙 준비 → 정지 | 0.4초 뒤 "준비 완료" |
| 흔들기 거부 | 준비 후 손목으로 빠르게 흔들기 10회 | 10회 모두 발사하지 않음 |
| 정상 하프스윙 | 하프스윙 20회 | 18회 이상 발사, 임팩트 표시가 영상과 ±50 ms 이내 |
| 포화 | 의도적으로 빠른 스윙 (안전 확보 후) | 포화 시 발사 중단 메시지 |
| TV 미러링 | Smart View → LG TV | 16:9 화면, 지연 체감 확인 |

**부호 보정**: 의도적으로 페이스를 연 스윙 10회와 닫은 스윙 10회를 기록해 `faceRollDeg` 부호를 확인합니다. 반대로 나오면 설정의 "페이스 방향 부호 반전"을 켜거나 코드 기본값을 바꿉니다. 경로(`planeShiftDeg`)도 인-아웃과 아웃-인 연습으로 같은 방법을 씁니다.

## 2단계: 휴대폰 + 런치모니터 동시 수집 (프로 골퍼)

### 장비
- 런치모니터: 볼 스피드, 발사각, 스핀(백·사이드), 스핀축, 출발 방향, 클럽 스피드, 페이스·경로를 측정하는 장비 (예: TrackMan, GCQuad, 또는 카메라식 측정기)
- 휴대폰 고정: 실제 클럽을 휘두르며 휴대폰 데이터를 얻으려면 **그립 끝(버트)에 휴대폰 마운트**를 단단히 고정하거나, 별도 IMU를 그립에 부착합니다. 안전 검토가 필수입니다.
- 대안: 실제 공을 치지 않고 휴대폰만 쥔 "미러 스윙"을 런치모니터 샷 직후에 따라 하게 하여 개인별 매핑을 학습합니다 (간접 방식, 정확도 낮음).
- 고속 카메라 1대 (240 fps 이상): 임팩트 시점 정답 표시용

### 시간 동기화
- 기록 시작 시 휴대폰으로 클럽 헤드를 바닥에 3번 가볍게 치는 동기화 동작 → 가속도 스파이크와 영상 프레임을 맞춤
- 앱의 CSV는 상대 시간(초)이므로 JSON 메타데이터의 `createdAt`과 런치모니터 샷 시각을 함께 기록

### 수집량 (1차 목표)

| 구분 | 인원 | 클럽 | 스윙 유형 | 반복 | 합계 |
|---|---|---|---|---|---|
| 프로 | 3명 | 드라이버, 7번, PW | 정상, 드로, 페이드, 하프, 느린 | 각 10 | 3 × 3 × 5 × 10 = 450 |
| 중·상급 아마추어 | 5명 | 7번 | 정상, 하프 | 각 15 | 150 |
| 초보 | 4명 | 7번 | 정상 | 20 | 80 |
| 스윙이 아닌 동작 | 4명 | - | 흔들기, 걷기, 들어 올리기, 떨어뜨림 모사(쿠션 위) | 각 10 | 160 |

- 골퍼 단위로 학습·검증을 나눌 수 있도록 **최소 12명**을 확보합니다.
- 프로에게는 의도한 구질(드로·페이드)과 실제 측정 구질을 모두 기록합니다. 의도 ≠ 결과인 샷도 버리지 않습니다.

### 기록 항목
- 앱 CSV + JSON (참가자 코드, 스윙 유형, 기기 모델, 센서 정보 자동 포함)
- 런치모니터 샷 결과 전체 (CSV 내보내기)
- 참가자 메타: 숙련도, 손잡이, 키 (선택)
- 개인정보: 이름 대신 코드만 사용, 동의서 별도 보관

## 3단계: 모델 개발 순서

1. **임팩트 시점 정확도**: 고속 영상 정답 대비 가상 임팩트 오차 분포 (목표 중앙값 ≤ 20 ms)
2. **파워 매핑**: 휴대폰 평면 최대 각속도 → 클럽 스피드 회귀 (골퍼 단위 교차검증)
3. **페이스·경로**: `faceRollDeg`, `planeShiftDeg` → 런치모니터 페이스 각·경로 회귀. 부호와 이득 계수 결정
4. **구질 분류**: 스핀축 3분류 (드로/스트레이트/페이드). 목표는 골퍼 독립 균형 정확도 0.6 이상
5. 결과가 기준을 넘으면 `physics-engine/src/game-config.js`의 계수를 데이터 기반 값으로 교체하고, 그 근거를 문서화

## 공개 데이터로 해결하지 못한 부분

| 문제 | 이유 | 필요한 데이터 |
|---|---|---|
| 휴대폰 센서 → 클럽 스피드 | 공개 데이터에 손에 쥔 휴대폰 IMU가 없음 | 2단계 동시 수집 |
| 페이스 각 추정의 부호·이득 | 합성 데이터로만 검증함 | 의도적 오픈/클로즈 스윙 + 런치모니터 |
| 경로 추정 | 스윙 평면 방위 변화가 실제 경로와 어떤 관계인지 미검증 | 인-아웃/아웃-인 스윙 + 런치모니터 |
| 구름(런) 거리 | CaddieSet의 Distance도 측정기 모델값임 | 실제 필드 착지·정지 지점 측정 |
| 다양한 휴대폰 | 기기마다 샘플링 속도와 센서 범위가 다름 | 기종 5종 이상에서 1단계 반복 |
| MultiSenseGolf 활용 | 이 환경에서 데이터 접근 불가 | 네트워크가 허용된 환경에서 다운로드 후 리드핸드 특징 분포 비교 |
